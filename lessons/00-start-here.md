# ようこそ！ここから始めよう（00-start-here）

> 所要時間: 約10〜15分 / 🌐 Webのみ / 準備不要\
> このページを読めば「GitHubで何が起きているのか」の全体像が分かります。暗記は不要です。

---

## まず結論：GitHubでは何をするの？

```text
1. 書類箱（Repository）を用意する
2. 書類（ファイル）を入れる
3. 変更を記録する（Commit）
4. 別の案を試す（Branch）
5. 合流していいか相談する（Pull Request）
6. 合流する（Merge）
7. やることを付箋に書く（Issue）
```

あなたはこれから、この7つを実際に触って覚えます。
今は名前だけ眺めてください。

---

## 1. Gitとは（PCの中の記録係）

Gitは**あなたのPCの中でファイルの履歴を記録する仕組み**です。

 concrete例：レポートを書いているとします。

```text
レポート_v1.docx
レポート_v2_修正.docx
レポート_v3_最終.docx
レポート_v3_最終_本当の最終.docx  ← あるある
```

Gitを使うとこうなります：

```text
レポート.docx ＋ 履歴（いつ・誰が・何を変えたか全部記録）
```

- いつでも過去に戻れる
- 何を変えたか差分が見られる
- ファイルを増やさなくていい

> 💻 ターミナルで使うのがGitです。`git commit` などがそれにあたります。

---

## 2. GitHubとは（ネット上の共有図書館）

GitHubは**Gitの記録をインターネット上に置いて共有するWebサービス**です。

```text
あなたのPC（Git）  ←→  GitHub（ネット）  ←→  仲間のPC（Git）
      自分の記録          みんなの集合場所          仲間の記録
```

- PCが壊れてもGitHubにあれば復元できる
- 離れた人と共同作業できる
- 相談（Pull Request）や付箋（Issue）の機能がある

> 🌐 ブラウザで使うのがGitHubです。

---

## 3. GitとGitHubの違い（重要・試験に出ます）

|  | Git | GitHub |
|---|---|---|
| どこにある？ | 自分のPC | インターネット |
| 何をする？ | 履歴を記録 | 履歴を共有・相談 |
| なくても動く？ | Gitだけでも記録はできる | GitHubだけでは記録できない（Gitが必要） |
| 例え | 日記を書くこと | 日記を持ち寄る交換ノート |

```text
Git（記録）なしにGitHub（共有）はできない。
GitHub（共有）なしでもGit（記録）はできる。
```

分からなくなったらこの図に戻ってきてください。

---

## 4. Repository（リポジトリ）とは

**プロジェクトの書類箱**です。略して「リポジトリ」「レポ」と呼びます。

- 1リポジトリ = 1プロジェクト（例：この教材全体が1つのリポジトリ）
- 中にファイル・履歴・相談・付箋が全部入っている
- GitHub上に作るもの（Remote）とPCに複製するもの（Local）がある

この教材のリポジトリ： `github_practics`

---

## 5. LocalとRemoteとは

- **Local（ローカル）**: あなたのPCの中。「手元の作業机」
- **Remote（リモート）**: GitHub上の共有場所。「みんなの本棚」

```text
[Local: あなたのPC]  --push-->  [Remote: GitHub]  --pull-->  [仲間のPC]
                     <--pull--               <--push--
```

- `push`: 机の成果を本棚に上げる
- `pull`: 本棚の最新を机に持ってくる
- `clone`: 本棚ごと机にコピーする（最初だけ）

---

## 6. Commit（コミット）とは

**変更のスナップショット（記録単位）**です。

```text
ファイルを編集 → git add（記録候補に入れる） → git commit（記録確定）
```

カメラで例えると：

- `add`: 写すものを選ぶ
- `commit`: シャッターを押す＋一言メモを添える（例：「見出しを追加」）

悪いメモ： `fix` `aaa` `test`
良いメモ： `Add search form` `Fix mobile header layout`

---

## 7. Branch（ブランチ）とは

**履歴の枝分かれ（安全な作業場所）**です。

```text
main  ●━━●━━●━━●  ← いつも動く本線
           \
feature/xxx ●━━●  ← 実験用の枝
```

- `main`: 本番・いつも正しい状態にしておく枝
- 作業用Branchで壊しても`main`は無事
- 完成したら合流（Merge）する

> ルール：**mainへの直接Pushは禁止**。必ずBranchを切ります。

---

## 8. Pull Request（プルリクエスト）とは

**「合流していいか確認してください」というお願い**です。略してPR。

```text
作業Branch完成 → PR作成 → 他の人が確認 → OKならMerge
```

- 変更点・理由・確認方法を書く
- コードレビュー（確認）の場所になる
- 一人でも自分でPRを作ってセルフレビューします（練習になる）

---

## 9. Merge（マージ）とは

**枝を合流させること**です。

```text
main:    ●━━●━━━━━●  ← 合流後
               \   /
feature:       ●━●
```

- Mergeされると作業Branchの内容が`main`に入る
- 競合（Conflict）が起きることもある → 後で体験します

---

## 10. Issue（イシュー）とは

**やること付箋（課題票）**です。

```text
Issue #5: ヘッダーを作る
- 目的： サイトの顔を作る
- 作業内容： ...
- 完了条件： ...
```

- 誰が・何を・どこまでやるかを可視化する
- BranchやPRと紐づける（例：`Closes #5`）
- 人数可変に対応できる（増えたらIssueを足す）

---

## 全体の流れ（個人開発の基本形）

```text
Issueを見る
 ↓ 🌐 Branch作成
 ↓ 💻 実装・Commit
 ↓ 💻 Push
 ↓ 🌐 Pull Request作成
 ↓ 🌐 Review（確認）
 ↓ 💻 修正（必要なら）
 ↓ 🌐 Approve → Merge
```

この流れを何度も回します。覚えなくてOK。体で覚えます。
