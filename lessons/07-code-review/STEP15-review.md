# STEP 15 — Code Reviewを体験する

## 🎯 このLessonの目的

「OK」だけ言わないレビューができるようになります。観点は3つ：良い点・問題点・改善提案。

## 📖 Learn

レビューは粗探しではありません。目的：

- バグ・誤字の早期発見
- 読みやすさ・保守性の向上
- 知識共有（なぜこう書いたかを知る）

良いレビューコメント例：

```text
良い点： 見出しの文言が具体的で分かりやすいです 👍
問題点： inputにlabelがなく、スクリーンリーダーで読み上げできません
提案： <label for="q">検索</label> を追加するのはどうでしょう？
```

悪い例： `OK` `LGTM` のみ。何を見たか分からない。

## 🖥 Try

### SOLO（1人）の場合

1. [examples/sample-pr](../../examples/sample-pr/README.md) を開く（BobのPRシナリオ）
2. 差分を読んで、以下3種のコメントをPR上で再現する（自分の練習リポジトリのPRでOK）：
   - 良い点を1件
   - 問題点を1件（答えはサンプルに記載）
   - 改善提案を1件
3. `Approve` と `Request changes` の違いを確認（Mergeせずに体験でOK）

### PAIR / TEAMの場合

実際の仲間のPRに上記3観点でレビューする。絵文字＋理由付きで書く。

## 💡 考えてみよう

- 厳しすぎるレビューと甘すぎるレビュー、どちらがチームを壊すでしょう？

## 🎯 Mission

- [ ] 3観点（良い点・問題点・提案）でコメントした
- [ ] 指摘→修正→再レビュー（Approve）の流れを体験した

## ✅ Check

- [ ] 「OK」だけでなく理由を書けた
- [ ] 人ではなくコードを主語にできた（例：「この行は〜」）

## 🚨 Troubleshooting

- レビュー相手がいない → sample-prのBob/CCharlieを使ってSOLOで可
- 批判と受け取られた → 感謝＋提案形にする（`〜していただけると助かります`）
