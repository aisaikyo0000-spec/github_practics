# STEP 13 — PRの書き方・セルフレビュー

## 🎯 このLessonの目的

「入れていいか判断できるPR」を書けるようになります。

## 📖 Learn

PRの目的： **変更内容をmainへ入れていいか他の人に確認してもらう場所**。
最低限書くこと（テンプレートに準拠）：

- 何を変更したか・なぜ・確認方法・関連Issue・チェックリスト

悪い例： `直しました。確認お願いします。`
良い例：下記Try参照。

## 🖥 Try

次回PRを作る時、本文をこう書いてください：

```markdown
## 何を変更したか
- トップページの見出しを「ようこそ」→「地域情報ポータルへようこそ」に変更

## なぜ変更したか
- Issue #10 のため。初めての訪問者に分かる文言にする

## 確認方法
- [ ] `examples/sample-project/index.html` をブラウザで開き見出しを確認

## 関連Issue
- Closes #10

## チェックリスト
- [ ] mainからBranchを切った
- [ ] 差分が最小限である
- [ ] 自分でFiles changedを確認した
```

セルフレビューの観点： 誤字・余計な差分・命名・表示崩れ。

## 💡 考えてみよう

- あなたがレビューされる側なら、どんなPRが助かりますか？

## 🎯 Mission

- [ ] テンプレート通りにPRを1件作成した（過去PRの編集でも可）
- [ ] Files changedを自分で確認して1件以上コメントした

## ✅ Check

- [ ] 5項目を欠かさず書けた
- [ ] `Closes #番号` でIssue連携できた

## 🚨 Troubleshooting

- テンプレートが出ない → `.github/PULL_REQUEST_TEMPLATE.md` がmainにあるか確認
